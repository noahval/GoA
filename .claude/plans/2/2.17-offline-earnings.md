# Offline Earnings

## Overview

This plan provides the **core offline earnings infrastructure** - timestamp verification and duration caps. It does NOT define job-specific earnings rates. Those belong to individual job plans (e.g., dishwash plan defines its own offline rate and progression).

**Core Goal**: Track offline duration, enforce caps, and trigger earnings calculation via JobBoardManager.

---

## Dependencies

- **1.x-nakama-server.md**: Provides server timestamp verification to prevent clock manipulation
- **1.15-notifications.md**: Provides `Global.show_notification()` for welcome-back messages

**Note**: This plan MUST be implemented before 2.18-job-board.md. The Job Board plan will reference the API contract defined here. This plan establishes:
1. The `OfflineEarningsManager` initialization order requirement
2. The `process_offline_session()` API contract that jobs must implement
3. The server-only time verification requirement (no local fallback for earnings)

## Core Mechanics

### Offline Cap

**Maximum Offline Duration**: Configurable via `offline_max_hours` variable (default: 2 hours)

```gdscript
var offline_max_hours: int = 2  # Modifiable for future upgrades
# Cap is calculated as: offline_max_hours * 3600 (converts hours to seconds)
```

- Stored as hours for readability and easy modification
- No upgrades in this plan (future plan will modify `offline_max_hours`)
- Simple, flat cap applied to all offline sessions
- Cap enforced at calculation time, not storage time

### Server Timestamp Verification

Following the Nakama server plan (1.x-nakama-server.md), use **server time ONLY** to prevent manipulation. No local fallback for earnings calculation.

**On Game Close/Save**:
```gdscript
# In NakamaClient.save_game() - already updates timestamp
Level1Vars.last_played_timestamp = Time.get_unix_time_from_system()
```

**On Game Load**:
```gdscript
# Use server time for verification (REQUIRED - no fallback)
var server_time = await NakamaClient.get_server_time()
if server_time == -1:  # Server unavailable
    # Deny offline earnings - game requires server connection anyway
    Global.show_notification("Cannot connect to server. No offline earnings awarded.", Global.NOTIFICATION_TYPE_WARNING)
    return

var elapsed_seconds = server_time - Level1Vars.last_played_timestamp
var capped_seconds = min(elapsed_seconds, offline_max_hours * 3600)
```

**Anti-Cheat Policy**: If server time is unavailable, offline earnings are **denied entirely**. The game's other systems require server connection, so this is acceptable.

**First Install Behavior**: On brand new install with no save data, `last_played_timestamp` is 0. The system sets it to current server_time and saves immediately (no earnings awarded). If server connection fails on first install, the timestamp remains 0 and will retry on next launch. This is acceptable since the game requires server connection for other systems.

### Earnings Calculation

**This plan only handles**:
1. Getting elapsed time (capped)
2. Calling `JobBoardManager.process_offline_session()` to calculate (not award) earnings
3. Saving game state with updated timestamp
4. Awarding currency ONLY after save succeeds
5. Displaying the welcome-back notification

**JobBoardManager (from 2.x-job-board.md) handles**:
- Which job is assigned
- Delegating to job-specific earning calculations
- Currency type determination
- Actual earnings math (via job-specific functions)
- **IMPORTANT**: Handlers CALCULATE earnings but DO NOT modify currency variables

**Critical Anti-Exploit Design**:
Currency is awarded AFTER successful save, not before. This prevents duplication exploits where players force save failures to repeatedly collect the same offline earnings.

```gdscript
# Simplified flow - calculate, save, then award
var elapsed_seconds = min(server_time - last_played_timestamp, OFFLINE_CAP)
var result = JobBoardManager.process_offline_session(elapsed_seconds)
# result contains: {earnings: int, currency: String, job_name: String}
# Currency NOT yet awarded - happens after save succeeds
```

### Notification on Return

When player returns after offline period:

```
Welcome back! You were away for 1 hour 30 minutes.

Overtime earnings (Dishwashing):
- Earned: 54 holes
```

If no idle job assigned:
```
Welcome back! You were away for 1 hour 30 minutes.

You didn't have an idle job assigned.
Visit the Job Board to set one up!
```

If exceeded cap:
```
Welcome back! You were away for 3 hours 12 minutes (capped at 2 hours 0 minutes).

Overtime earnings (Dishwashing):
- Earned: 72 holes

You hit your offline cap!
```

**Time Format**: Human-readable "X hours Y minutes" (not decimal hours like "1.5 hours")

## Implementation Steps

### Step 1: Add Server Time API to NakamaClient

**File**: `nakama_client.gd`

**Prerequisites**: The server-side RPC `get_server_time` must be implemented in Nakama first (see 1.x-nakama-server.md). This RPC should return the current server Unix timestamp.

```gdscript
# Fetch current server time (Unix timestamp)
# Returns -1 if server unavailable (caller must handle - DO NOT award offline earnings)
func get_server_time() -> int:
    if not is_authenticated:
        DebugLogger.error("Cannot get server time: Not authenticated")
        return -1  # No fallback - caller denies offline earnings

    # Use Nakama's server time RPC (must be implemented server-side)
    var result = await client.rpc_async(session, "get_server_time", "{}")

    if result.is_exception():
        DebugLogger.error("Server time fetch failed: " + result.get_exception().message)
        return -1  # No fallback - caller denies offline earnings

    var payload = JSON.parse_string(result.payload)
    if not payload.has("server_time"):
        DebugLogger.error("Server time missing from response")
        return -1

    return int(payload.server_time)
```

**Critical Change**: Returns `-1` on failure instead of falling back to local time. This prevents clock manipulation exploits.

### Step 2: Offline Earnings Manager

**File**: `offline_earnings_manager.gd` (singleton autoload)

**Responsibilities**:
- Fetch server time (deny earnings if unavailable)
- Calculate elapsed duration (with cap)
- Update last_played_timestamp (save immediately on first launch)
- Call JobBoardManager for earnings (all job logic lives there)
- Show welcome-back notification

**Initialization Order Rule**: OfflineEarningsManager MUST be initialized AFTER:
- NakamaClient (uses get_server_time())
- Global (uses show_notification())
- JobBoardManager (calls process_offline_session())

Configure in `project.godot` autoload order accordingly.

```gdscript
extends Node

var offline_max_hours: int = 2  # Modifiable for upgrades

func process_offline_earnings():
    var server_time = await NakamaClient.get_server_time()

    # Deny earnings if server unavailable (anti-cheat)
    if server_time == -1:
        Global.show_notification("Cannot connect to server. No offline earnings awarded.", Global.NOTIFICATION_TYPE_WARNING)
        return

    # First launch - set timestamp and save immediately
    if Level1Vars.last_played_timestamp == 0:
        Level1Vars.last_played_timestamp = server_time
        var save_success = await NakamaClient.save_game()
        if not save_success:
            DebugLogger.warn("First launch timestamp save failed - will retry next launch")
        return

    var elapsed_seconds = server_time - Level1Vars.last_played_timestamp
    var offline_cap_seconds = offline_max_hours * 3600
    var capped_seconds = min(elapsed_seconds, offline_cap_seconds)

    # CRITICAL ANTI-EXPLOIT ORDER:
    # 1. Calculate earnings (handlers DO NOT award currency yet)
    # 2. Update timestamp in memory
    # 3. Save to server
    # 4. Award currency ONLY if save succeeds

    # Calculate earnings (does NOT modify currency variables)
    var result = JobBoardManager.process_offline_session(capped_seconds)

    # Update timestamp in memory (not yet persisted)
    Level1Vars.last_played_timestamp = server_time

    # Save to server - timestamp update persisted here
    var save_success = await NakamaClient.save_game()
    if not save_success:
        # Revert timestamp - earnings will be recalculated next launch
        Level1Vars.last_played_timestamp = server_time - elapsed_seconds
        Global.show_notification("Failed to save offline earnings. Please reconnect.", Global.NOTIFICATION_TYPE_WARNING)
        return

    # NOW award currency (save succeeded, safe to modify)
    _award_currency(result)

    # Show notification with awarded earnings
    _show_notification(elapsed_seconds, capped_seconds, result)

func _show_notification(elapsed: int, capped: int, result: Dictionary):
    var offline_cap_seconds = offline_max_hours * 3600
    var exceeded = elapsed > offline_cap_seconds

    var message = "Welcome back! You were away for %s" % _format_time(elapsed)
    if exceeded:
        message += " (capped at %s)" % _format_time(capped)
    message += ".\n\n"

    if result.is_empty():
        message += "You didn't have an idle job assigned.\n"
        message += "Visit the Job Board to set one up!"
    else:
        message += "Overtime earnings (%s):\n" % result.job_name
        message += "- Earned: %d %s\n\n" % [result.earnings, result.currency]
        if exceeded:
            message += "You hit your offline cap!"

    Global.show_notification(message, Global.NOTIFICATION_TYPE_INFO)

func _award_currency(result: Dictionary):
    """Award currency to player based on earnings result"""
    if result.is_empty():
        return  # No job assigned, no earnings

    # Apply currency modification based on type
    var amount = result.earnings
    var currency_type = result.currency

    match currency_type:
        "holes":
            Level1Vars.holes += amount
        "coal":
            Level1Vars.coal += amount
        # Add other currency types as jobs are implemented
        _:
            DebugLogger.error("Unknown currency type: " + currency_type)

func _format_time(seconds: int) -> String:
    """Convert seconds to human-readable 'X hours Y minutes' format"""
    var hours = seconds / 3600
    var minutes = (seconds % 3600) / 60
    return "%d hour%s %d minute%s" % [hours, "s" if hours != 1 else "", minutes, "s" if minutes != 1 else ""]
```

## Notes

### Design Decisions

**Why 2-hour flat cap?**
- Simple baseline before upgrades unlock
- Reasonable for short breaks/sleep
- Easy to understand and communicate
- Future plan handles overtime progression

**Why server time verification?**
- Prevents local clock manipulation
- Maintains fair progression
- Already implemented in Nakama plan (1.17)
- No fallback to local time (denies earnings if server down)
- Acceptable trade-off since game requires server for other systems

**Why no minimum offline time?**
- Removed based on user feedback
- Any offline time counts (even 1 minute)
- Simpler logic, better UX

**Why no job-specific logic here?**
- Each job defines its own idle rate and progression
- Dishwashing plan handles dishwash-specific idle rate (via mugs_washed)
- Keeps this plan focused on cap/timestamp logic

### Separation of Concerns

| This Plan (2.17 Offline Earnings) | Job Board Plan (2.18-job-board.md) | Job Plans (e.g., 2.19.8 Dishwash) |
|-----------------------------------|-----------------------------------|-----------------------------------|
| Server timestamp verification | Job assignment (`current_idle_job`) | Job-specific progression systems |
| Duration cap (`offline_max_hours`) | Routing to job-specific functions | Idle earning rate calculations |
| OfflineEarningsManager singleton | Job unlocking/discovery | Currency type per job |
| Welcome-back notification UI | Navigation to job scenes | Active play → idle rate improvement |
| Denying earnings on server failure | API contract definition | Self-registration with JobBoardManager |
| Initialization order enforcement | | |

**Call Flow**: Game Load → OfflineEarningsManager → JobBoardManager → Job-specific function → Currency awarded

**API Contract for Job Board Plan (2.18)**:
Jobs must register a handler via `JobBoardManager.register_job(job_id, handler_callable)` where handler returns:
```gdscript
{
    "earnings": int,      # Amount earned (calculated, NOT awarded yet)
    "currency": String,   # "holes", "coal", etc.
    "job_name": String    # Display name for notification
}
```

**CRITICAL**: Handlers MUST only calculate earnings and return the result. They MUST NOT modify currency variables (Level1Vars.holes, etc.). Currency is awarded by OfflineEarningsManager AFTER save succeeds to prevent duplication exploits.

This contract is enforced by this plan and MUST be followed by 2.18-job-board.md and all job-specific plans.
