# Nakama Account Migration System

## Overview
Handle migration when players switch from device ID authentication to username/password or Google authentication.

**Parent Plan**: [../1.17-nakama-server.md](../1.17-nakama-server.md) (index)
**Depends On**: [1.17.1-core-client.md](1.17.1-core-client.md), [1.17.2-authentication.md](1.17.2-authentication.md), [1.17.3-cloud-storage.md](1.17.3-cloud-storage.md), [1.17.4-serialization.md](1.17.4-serialization.md)

## Purpose
- Link device ID to username/Google account (preferred approach)
- Migrate save data between accounts when linking is not possible
- Handle conflicts when both accounts have saves
- Provide intuitive UI for conflict resolution

---

## Architecture Decision: Account Linking vs Migration

**Preferred Approach**: Account Linking (Nakama native feature)
- Link device ID to username/Google account
- User can authenticate with EITHER method afterward
- No data migration needed - accounts are merged server-side
- Simpler implementation, better UX

**Fallback Approach**: Server-Side Migration RPC
- Used when account linking fails (rare)
- Server reads both accounts' storage
- Copies data from device account to username account
- Requires server-side RPC implementation

**Why Not Client-Side Migration?**
- Nakama sessions are user-specific - can't read another user's private storage from client
- Would require complex session switching
- Server-side is atomic and reliable

## Implementation

### 5.1 Account Linking (Preferred)

Link device ID to username/Google account so user can authenticate with either method.

**Add to NakamaManager (nakama_client.gd)**:

```gdscript
# Store device ID for linking later
var device_id: String = ""

func _ready():
	# ... existing code ...

	# Store device ID for potential linking
	device_id = _get_device_id()

func link_device_to_current_account() -> Dictionary:
	"""
	Links device ID to currently authenticated account.
	Returns: {success: bool, error: String}
	"""
	if not is_authenticated:
		return {
			"success": false,
			"error": "not_authenticated"
		}

	var result = await client.link_device_async(session, device_id)

	if result.is_exception():
		var error_msg = result.get_exception().message
		DebugLogger.error("Account linking failed: " + error_msg, "NAKAMA")

		# Check if device already linked to another account
		if "already" in error_msg.to_lower():
			return {
				"success": false,
				"error": "device_already_linked"
			}

		return {
			"success": false,
			"error": "link_failed",
			"message": error_msg
		}

	DebugLogger.info("Device ID linked to account", "NAKAMA")
	return {
		"success": true,
		"error": ""
	}
```

### 5.2 Check for Migration Scenario

Determines if migration is needed when account linking fails.

**Add to NakamaManager**:

```gdscript
func check_for_migration_needed(old_device_id: String) -> Dictionary:
	"""
	Checks if device ID account has save data.
	Called after account linking fails (device already linked to different account).
	Returns: {needs_migration: bool, error: String}
	"""
	if not is_authenticated:
		return {
			"needs_migration": false,
			"error": "not_authenticated"
		}

	# Call server RPC to check if device account has save
	var payload = {"device_id": old_device_id}
	var result = await client.rpc_async(session, "check_device_save", JSON.stringify(payload))

	if result.is_exception():
		var error = result.get_exception().message
		DebugLogger.error("Migration check failed: " + error, "NAKAMA")

		if "network" in error.to_lower() or "timeout" in error.to_lower():
			return {
				"needs_migration": false,
				"error": "network_error"
			}

		return {
			"needs_migration": false,
			"error": "check_failed"
		}

	var response = JSON.parse_string(result.payload)

	return {
		"needs_migration": response.get("has_save", false),
		"device_save_summary": response.get("device_summary", {}),
		"account_save_summary": response.get("account_summary", {}),
		"has_conflict": response.get("has_conflict", false),
		"error": ""
	}
```

### 5.3 Migrate Save via Server RPC

Calls server-side RPC to migrate save data.

**Add to NakamaManager**:

```gdscript
func migrate_save_from_device(device_id_to_migrate: String, overwrite_current: bool = false) -> Dictionary:
	"""
	Migrates save from device ID account to current account.

	Args:
		device_id_to_migrate: Device ID to migrate from
		overwrite_current: If true, overwrites current account save. If false, only migrates if no save exists.

	Returns: {success: bool, error: String}
	"""
	if not is_authenticated:
		return {
			"success": false,
			"error": "not_authenticated"
		}

	var payload = {
		"device_id": device_id_to_migrate,
		"overwrite": overwrite_current
	}

	var result = await client.rpc_async(session, "migrate_device_save", JSON.stringify(payload))

	if result.is_exception():
		var error = result.get_exception().message
		DebugLogger.error("Migration failed: " + error, "NAKAMA")

		migration_completed.emit(false)

		return {
			"success": false,
			"error": "migration_failed",
			"message": error
		}

	var response = JSON.parse_string(result.payload)

	if response.get("success", false):
		DebugLogger.info("Save migrated successfully", "NAKAMA")
		migration_completed.emit(true)

		# Reload game state from cloud
		await load_game()

		return {
			"success": true,
			"error": ""
		}
	else:
		DebugLogger.error("Migration failed: " + response.get("error", "unknown"), "NAKAMA")
		migration_completed.emit(false)

		return {
			"success": false,
			"error": response.get("error", "unknown")
		}
```

### 5.4 Get Save Summary for Conflict Resolution

Formats save data for display in conflict UI.

**Add to NakamaManager**:

```gdscript
func format_save_summary(summary: Dictionary) -> Dictionary:
	"""
	Formats save summary for UI display.
	Input: Raw summary from server (timestamps, stats, currency, play time)
	Output: Formatted strings for display
	"""
	if summary.is_empty():
		return {
			"last_played_str": "Never",
			"play_time_str": "0 hours",
			"total_stats": 0,
			"copper": 0
		}

	# Format timestamp
	var timestamp = summary.get("last_played", 0)
	var last_played_str = "Never"
	if timestamp > 0:
		var datetime = Time.get_datetime_dict_from_unix_time(timestamp)
		last_played_str = "%04d-%02d-%02d %02d:%02d" % [
			datetime.year,
			datetime.month,
			datetime.day,
			datetime.hour,
			datetime.minute
		]

	# Format play time
	var play_hours = summary.get("total_play_hours", 0.0)
	var play_time_str = "%.1f hours" % play_hours

	# Calculate total stats
	var stats = summary.get("stats", {})
	var total_stats = (
		stats.get("strength", 0) +
		stats.get("constitution", 0) +
		stats.get("dexterity", 0) +
		stats.get("wisdom", 0) +
		stats.get("intelligence", 0) +
		stats.get("charisma", 0)
	)

	# Get currency
	var currency = summary.get("currency", {})
	var copper = currency.get("copper", 0)

	return {
		"last_played_str": last_played_str,
		"play_time_str": play_time_str,
		"total_stats": total_stats,
		"copper": copper,
		"stats": stats
	}

func recommend_save(device_summary: Dictionary, account_summary: Dictionary) -> String:
	"""
	Recommends which save to keep based on play time and recency.
	Returns: "device", "account", or "ask_user"
	"""
	var device_hours = device_summary.get("total_play_hours", 0.0)
	var account_hours = account_summary.get("total_play_hours", 0.0)
	var play_time_diff = abs(device_hours - account_hours)

	# If play time difference is less than 1 hour, recommend newer save
	if play_time_diff < 1.0:
		var device_time = device_summary.get("last_played", 0)
		var account_time = account_summary.get("last_played", 0)
		return "device" if device_time > account_time else "account"

	# Significant difference - let user choose
	return "ask_user"
```

### 5.5 Integration with Authentication Flow

**When**: After username/password or Google authentication succeeds

**Where**: In authentication completion handler (add to [1.17.2-authentication.md](1.17.2-authentication.md))

**Flow**:

```gdscript
# In authenticate_username_password() or authenticate_google()
# After successful authentication:

func _on_authentication_succeeded(new_session: NakamaSession):
	session = new_session
	_set_auth_state(session)

	# Try to link device ID to this account
	var link_result = await link_device_to_current_account()

	if link_result.success:
		# Device linked successfully - no migration needed
		DebugLogger.info("Device linked to account", "NAKAMA")
		authentication_succeeded.emit(_get_session_data())
	elif link_result.error == "device_already_linked":
		# Device already linked to DIFFERENT account - check for migration
		var migration_check = await check_for_migration_needed(device_id)

		if migration_check.error == "network_error":
			# Network error - show retry dialog
			_show_migration_network_error()
		elif migration_check.needs_migration:
			# Device account has save data - show migration UI
			_show_migration_ui(migration_check)
		else:
			# No save on device account - proceed normally
			authentication_succeeded.emit(_get_session_data())
	else:
		# Other linking error - log and proceed
		DebugLogger.warning("Account linking failed: " + link_result.error, "NAKAMA")
		authentication_succeeded.emit(_get_session_data())
```

		# User cancelled - just proceed with current account save
		DebugLogger.info("Migration cancelled by user", "NAKAMA")

		return

	if result.success:

## Server-Side Implementation (Nakama)

**Required RPCs** (implement on Nakama server):

### check_device_save RPC

```lua
-- File: main.lua on Nakama server
local function check_device_save_rpc(context, payload)
	local nk = require("nakama")
	local json = require("json")

	local data = json.decode(payload)
	local device_id = data.device_id

	if not device_id then
		error("device_id required")
	end

	-- Get user ID for device authentication
	local account = nk.account_get_id(device_id)
	if not account then
		-- Device not registered
		return json.encode({
			has_save = false,
			has_conflict = false
		})
	end

	local device_user_id = account.user.id
	local current_user_id = context.user_id

	-- Read device account save
	local device_objects = nk.storage_read({
		{collection = "player_data", key = "game_save", user_id = device_user_id}
	})

	-- Read current account save
	local current_objects = nk.storage_read({
		{collection = "player_data", key = "game_save", user_id = current_user_id}
	})

	local has_device_save = #device_objects > 0
	local has_current_save = #current_objects > 0

	local response = {
		has_save = has_device_save,
		has_conflict = has_device_save and has_current_save
	}

	-- Add summaries if saves exist
	if has_device_save then
		local device_save = json.decode(device_objects[1].value)
		response.device_summary = extract_summary(device_save)
	end

	if has_current_save then
		local current_save = json.decode(current_objects[1].value)
		response.account_summary = extract_summary(current_save)
	end

	return json.encode(response)
end

local function extract_summary(save_data)
	local global_data = save_data.global or {}
	local level1_data = save_data.level1_vars or {}

	return {
		last_played = save_data.timestamp or 0,
		total_play_hours = (global_data.total_play_length or 0) / 3600.0,
		stats = {
			strength = global_data.strength or 1,
			constitution = global_data.constitution or 1,
			dexterity = global_data.dexterity or 1,
			wisdom = global_data.wisdom or 1,
			intelligence = global_data.intelligence or 1,
			charisma = global_data.charisma or 1
		},
		currency = level1_data.currency or {copper = 0, silver = 0, gold = 0, platinum = 0}
	}
end

nk.register_rpc(check_device_save_rpc, "check_device_save")
```

### migrate_device_save RPC

```lua
local function migrate_device_save_rpc(context, payload)
	local nk = require("nakama")
	local json = require("json")

	local data = json.decode(payload)
	local device_id = data.device_id
	local overwrite = data.overwrite or false

	if not device_id then
		error("device_id required")
	end

	-- Get device account user ID
	local account = nk.account_get_id(device_id)
	if not account then
		return json.encode({
			success = false,
			error = "device_not_found"
		})
	end

	local device_user_id = account.user.id
	local current_user_id = context.user_id

	-- Read device save
	local device_objects = nk.storage_read({
		{collection = "player_data", key = "game_save", user_id = device_user_id}
	})

	if #device_objects == 0 then
		return json.encode({
			success = false,
			error = "no_device_save"
		})
	end

	-- Check if current account has save (if not overwriting)
	if not overwrite then
		local current_objects = nk.storage_read({
			{collection = "player_data", key = "game_save", user_id = current_user_id}
		})

		if #current_objects > 0 then
			return json.encode({
				success = false,
				error = "save_exists_no_overwrite"
			})
		end
	end

	-- Copy save to current account
	local device_save_value = device_objects[1].value

	nk.storage_write({
		{
			collection = "player_data",
			key = "game_save",
			user_id = current_user_id,
			value = device_save_value,
			permission_read = 2,  -- Owner only
			permission_write = 1  -- Owner only
		}
	})

	-- Optionally: Delete device save to prevent confusion
	-- nk.storage_delete({
	--     {collection = "player_data", key = "game_save", user_id = device_user_id}
	-- })

	return json.encode({
		success = true
	})
end

nk.register_rpc(migrate_device_save_rpc, "migrate_device_save")
```

## Error Handling

### Network Errors
- Show retry dialog with "Retry" / "Continue Anyway"
- "Continue Anyway" proceeds with account save (no migration)

### RPC Failures
- Log error details
- Show user-friendly error message
- Offer retry option

### Migration Failures
- Keep original account save intact (no data loss)
- Show error + retry option
- User can choose "Continue Anyway" to proceed without migration

### Partial Migration
- Server-side operation is atomic (all-or-nothing)
- Client reload after migration ensures consistent state

## Notes

**Decision: Account Linking Over Migration**
- **Rationale**: Nakama provides native account linking - simpler and more reliable
- **Benefit**: User can use EITHER auth method after linking (device OR username)
- **Fallback**: Server RPC migration only needed if linking fails (rare edge case)

**Decision: Server-Side Migration**
- **Rationale**: Nakama sessions are user-specific - can't read other users' private storage from client
- **Benefit**: Atomic operation, no client-side session juggling
- **Trade-off**: Requires server-side implementation

**Decision: Automatic Conflict Recommendation**
- **Rationale**: Most conflicts have obvious "right" choice (newer save with similar play time)
- **Benefit**: Reduces friction for common case
- **Safety**: Only auto-recommends when saves are similar - user still chooses

**Decision: No Auto-Delete of Device Save**
- **Rationale**: Preserve data in case of migration issues
- **Trade-off**: Device account remains with old save (orphaned)
- **Mitigation**: Document that device auth will show old save if used again
