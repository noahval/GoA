# Nakama Account Migration System

## Overview

Handle migration when players switch from device ID to username/password or Google authentication.

**Parent Plan**: [../1.17-nakama-server.md](../1.17-nakama-server.md)
**Depends On**: [1.17.1-core-client.md](1.17.1-core-client.md), [1.17.2-authentication.md](1.17.2-authentication.md), [1.17.3-cloud-storage.md](1.17.3-cloud-storage.md)

---

## Approach: Account Linking (Preferred)

Use Nakama's native account linking to merge device ID with username/Google account.

**Benefits**:
- User can authenticate with EITHER method afterward
- No data migration needed - same account, multiple auth methods
- Simpler implementation

**Fallback**: Server-side RPC migration when linking fails (device already linked to different account).

---

## Migration Flow

```
User authenticates with username/Google
              |
              v
       Link device ID
              |
     +--------+--------+
     |                 |
  Success           Failure (device linked elsewhere)
     |                 |
     v                 v
   Done!         Check device save (RPC)
                       |
              +--------+--------+
              |                 |
         No save            Has save
              |                 |
              v                 v
           Done!          Show migration UI
                               |
                    +----------+----------+
                    |                     |
               No conflict           Has conflict
                    |                     |
                    v                     v
             "Migrate/Fresh"      Show both saves
                    |             User picks one
                    +----------+----------+
                               |
                               v
                    Migrate via RPC (if needed)
                               |
                               v
                         Reload game
```

### Authentication Integration

In auth completion (username/Google), after session is set:

1. Call `link_device_to_current_account()`
2. If error == "device_already_linked": call `check_for_migration_needed()`
3. If `needs_migration`: show migration UI
4. Otherwise: proceed normally

### Migration UI

Simple popup showing:
- **No conflict**: "Device save found. Migrate or Start Fresh?"
- **Conflict**: Side-by-side comparison (play time, last played, stats) with "Use Device / Use Account"

Display fields: last_played timestamp, total_play_hours, total_stats, copper

## Server Implementation (Nakama Lua)

### check_device_save RPC

Input: `{device_id: String}`

Behavior:
1. Find user ID for device_id
2. Read both device and current user's saves from `player_data/game_save`
3. Return save summaries if they exist

Output: `{has_save: bool, has_conflict: bool, device_summary: Dict, account_summary: Dict}`

### migrate_device_save RPC

Input: `{device_id: String, overwrite: bool}`

Behavior:
1. Read device account's save
2. If `!overwrite` and current account has save: error
3. Copy device save to current account's storage

Output: `{success: bool, error: String}`

---

## Error Handling

| Error | User Action |
|-------|-------------|
| Network error on check | "Retry / Continue Anyway" |
| Migration RPC fails | "Retry / Continue Anyway" (keeps existing account save) |
| Cancel at any point | Proceeds with account save |

Server migration is atomic - partial writes aren't possible.
