# Nakama Authentication Methods

## Overview
Implement all three authentication methods for Nakama: Device ID, Email/Password, and Google OAuth.

**Parent Plan**: [../1.17-nakama-server.md](../1.17-nakama-server.md) (index)
**Depends On**: [1.17.1-core-client.md](1.17.1-core-client.md)
**Reference Docs**: [.claude/docs/nakama-integration.md](.claude/docs/nakama-integration.md) (authority for API patterns)

## Purpose
- Device ID auth for low-friction cloud saves
- Email/Password for portable accounts across devices
- Google OAuth for web builds
- Session persistence across app restarts
- Hybrid cloud/local save system (cloud when authenticated, local fallback when offline)
- Connection recovery with retry logic

**Save Strategy**: Authentication enables cloud saves. Players can skip authentication and use local saves (see LocalSaveManager). Players can later authenticate to migrate local → cloud.

## Implementation

### 2.1 Device ID Authentication
Cloud-based authentication using device ID - no username/password required.

**Purpose**: Low-friction authentication that still provides cloud saves.

**API**: Matches [nakama-integration.md:91-108](.claude/docs/nakama-integration.md#L91-L108)

```gdscript
func authenticate_device(device_id: String = "") -> bool:
	if device_id.is_empty():
		device_id = _get_device_id()

	var result = await client.authenticate_device_async(device_id, null, true, {})

	if result.is_exception():
		var error = result.get_exception().message
		DebugLogger.error("Device auth failed: " + error, "NAKAMA")
		authentication_failed.emit(error)
		return false

	session = result as NakamaSession
	_set_auth_state(session)
	authentication_succeeded.emit(_get_session_data())

	# Migrate local save to cloud if exists
	await _migrate_local_save_if_exists()

	return true

func _get_device_id() -> String:
	var id = OS.get_unique_id()
	if id.is_empty():
		# Web builds may return empty - use persistent UUID
		id = _load_or_create_web_device_id()
	return id

func _load_or_create_web_device_id() -> String:
	const WEB_ID_PATH = "user://web_device_id.dat"
	if FileAccess.file_exists(WEB_ID_PATH):
		var file = FileAccess.open(WEB_ID_PATH, FileAccess.READ)
		if file:
			return file.get_as_text().strip_edges()

	# Generate new UUID
	var uuid = _generate_uuid()
	var file = FileAccess.open(WEB_ID_PATH, FileAccess.WRITE)
	if file:
		file.store_string(uuid)
	return uuid

func _generate_uuid() -> String:
	# Simple UUID v4 generation
	var chars = "0123456789abcdef"
	var uuid = ""
	for i in range(32):
		if i == 8 or i == 12 or i == 16 or i == 20:
			uuid += "-"
		uuid += chars[randi() % 16]
	return uuid
```

**Note**: Device ID creates a CLOUD account linked to this device. Not offline mode - cloud auth without username/password.

### 2.2 Email/Password Authentication
For players who want portable accounts accessible from any device.

**Purpose**: Manual account creation and login with secure password hashing.

**API**: Matches [nakama-integration.md:109-136](.claude/docs/nakama-integration.md#L109-L136)

**Security**: Uses Nakama's built-in `authenticate_email_async()` which handles password hashing server-side (no custom hooks needed).

```gdscript
func authenticate_email(email: String, password: String, create_account: bool, username: String = "") -> bool:
	# Validate inputs client-side (fail fast)
	if email.length() < 3:
		authentication_failed.emit("Email must be at least 3 characters")
		return false

	if password.length() < 8:
		authentication_failed.emit("Password must be at least 8 characters")
		return false

	# If creating account and no username provided, use email prefix
	if create_account and username.is_empty():
		username = email.split("@")[0]

	var result = await client.authenticate_email_async(email, password, username, create_account, {})

	if result.is_exception():
		var error = result.get_exception().message
		DebugLogger.error("Email auth failed: " + error, "NAKAMA")
		authentication_failed.emit(_sanitize_auth_error(error))
		return false

	session = result as NakamaSession
	_set_auth_state(session)
	authentication_succeeded.emit(_get_session_data())

	# Migrate local save to cloud if exists
	await _migrate_local_save_if_exists()

	return true

func _sanitize_auth_error(error: String) -> String:
	# Prevent username enumeration - vague messages for security
	if "already exists" in error.to_lower():
		return "Email already registered"
	if "not found" in error.to_lower() or "invalid" in error.to_lower():
		return "Invalid email or password"
	return "Authentication failed. Please try again."
```

**Requirements**:
- Email: 3+ characters (can be arbitrary username, doesn't need to be real email)
- Password: 8+ characters (enforced client-side and server-side)
- Username: Optional display name, defaults to email prefix

**No Server Hooks Required**: Nakama handles password hashing internally with bcrypt.

### 2.4 Account Linking (Device ID → Email Upgrade)
Allow device ID users to upgrade to email/password for cross-device portability.

**Flow**: Player using device ID can later add email/password to same account.

```gdscript
func link_email_to_account(email: String, password: String) -> bool:
	if not is_authenticated:
		DebugLogger.error("Must be authenticated to link email", "NAKAMA")
		return false

	# Validate inputs
	if email.length() < 3 or password.length() < 8:
		authentication_failed.emit("Invalid email or password format")
		return false

	# Link email to existing authenticated session
	var result = await client.link_email_async(session, email, password)

	if result.is_exception():
		var error = result.get_exception().message
		DebugLogger.error("Email linking failed: " + error, "NAKAMA")
		authentication_failed.emit("Failed to link email: " + error)
		return false

	DebugLogger.info("Email linked successfully to account", "NAKAMA")
	return true
```

**Usage**: Show "Add Email/Password" button in settings for device ID users.

### 2.5 Helper Functions

```gdscript
func _set_auth_state(nakama_session: NakamaSession):
	is_authenticated = true
	user_id = nakama_session.user_id
	username = nakama_session.username
	session = nakama_session
	_save_session_data(nakama_session)
	DebugLogger.info("Authenticated as: " + username, "NAKAMA")

func _clear_auth_state():
	is_authenticated = false
	user_id = ""
	username = ""
	session = null
	DebugLogger.info("Auth state cleared", "NAKAMA")

func _get_session_data() -> Dictionary:
	return {
		"user_id": user_id,
		"username": username,
		"session": session
	}

func logout():
	_clear_auth_state()
	_clear_session_data()
	DebugLogger.info("User logged out", "NAKAMA")
```

### 2.6 Session Persistence
Store session tokens to avoid re-authentication on every launch.

**Save Session Data** (token + refresh token + username):

```gdscript
const SESSION_DATA_PATH = "user://nakama_session.json"

func _save_session_data(nakama_session: NakamaSession):
	var data = {
		"token": nakama_session.token,
		"refresh_token": nakama_session.refresh_token,
		"username": nakama_session.username,
		"user_id": nakama_session.user_id
	}
	var file = FileAccess.open(SESSION_DATA_PATH, FileAccess.WRITE)
	if file:
		file.store_string(JSON.stringify(data))
		DebugLogger.info("Session data saved", "NAKAMA")
	else:
		DebugLogger.error("Failed to save session data", "NAKAMA")
```

**Load Session Data**:

```gdscript
func _load_session_data() -> Dictionary:
	if not FileAccess.file_exists(SESSION_DATA_PATH):
		return {}

	var file = FileAccess.open(SESSION_DATA_PATH, FileAccess.READ)
	if not file:
		return {}

	var json_string = file.get_as_text()
	var data = JSON.parse_string(json_string)
	if data == null:
		return {}

	return data
```

**Restore Session**:

```gdscript
func restore_session() -> bool:
	var data = _load_session_data()
	if data.is_empty():
		DebugLogger.info("No saved session found", "NAKAMA")
		return false

	var token = data.get("token", "")
	var refresh_token = data.get("refresh_token", "")

	if token.is_empty():
		return false

	# Restore session from tokens
	session = NakamaSession.new()
	session.token = token
	session.refresh_token = refresh_token

	# Check if expired locally
	if session.is_expired():
		DebugLogger.info("Stored session expired locally", "NAKAMA")
		_clear_session_data()
		return false

	# Validate with server (catches server-side invalidation)
	var account = await client.get_account_async(session)
	if account.is_exception():
		DebugLogger.info("Session invalid on server", "NAKAMA")
		_clear_session_data()
		return false

	# Session valid - restore auth state
	is_authenticated = true
	user_id = data.get("user_id", session.user_id)
	username = data.get("username", account.user.username)

	DebugLogger.info("Session restored for user: " + username, "NAKAMA")
	authentication_succeeded.emit(_get_session_data())
	return true

func _clear_session_data():
	if FileAccess.file_exists(SESSION_DATA_PATH):
		DirAccess.remove_absolute(SESSION_DATA_PATH)
	DebugLogger.info("Session data cleared", "NAKAMA")
```

### 2.7 Startup Connection & Retry Logic
Handle connection failures during startup with retry modal.

**Signals**:
```gdscript
signal connection_recovery_requested(retry_count: int)
signal connection_recovery_cancelled()
```

**Connection Logic**:

```gdscript
const MAX_RETRY_ATTEMPTS = 3
const RETRY_DELAYS = [1.0, 2.0, 4.0]  # Exponential backoff in seconds

func attempt_startup_connection() -> bool:
	# Try to restore existing session first
	var data = _load_session_data()
	if not data.is_empty():
		var restored = await _restore_session_with_retry()
		if restored:
			return true

	# No session to restore - return false to show login UI
	DebugLogger.info("No valid session, showing login options", "NAKAMA")
	return false

func _restore_session_with_retry() -> bool:
	for attempt in range(MAX_RETRY_ATTEMPTS):
		var success = await restore_session()
		if success:
			return true

		# Check if it's a network error vs invalid session
		var last_error = _get_last_error()
		if not _is_network_error(last_error):
			# Session is invalid, not a network issue - don't retry
			DebugLogger.info("Session invalid, not retrying", "NAKAMA")
			return false

		if attempt < MAX_RETRY_ATTEMPTS - 1:
			DebugLogger.info("Retry attempt " + str(attempt + 1) + " failed, waiting...", "NAKAMA")
			await get_tree().create_timer(RETRY_DELAYS[attempt]).timeout

	# All retries exhausted - emit signal for UI to show modal
	connection_recovery_requested.emit(MAX_RETRY_ATTEMPTS)
	return false

var _last_error_message: String = ""

func _get_last_error() -> String:
	return _last_error_message

func _is_network_error(error: String) -> bool:
	if error.is_empty():
		return false

	var network_keywords = ["network", "timeout", "unreachable", "connection", "timed out", "dns"]
	var error_lower = error.to_lower()

	for keyword in network_keywords:
		if keyword in error_lower:
			return true

	return false

func retry_connection() -> bool:
	# Called when user clicks Retry in modal - single attempt
	var success = await restore_session()

	if not success:
		# Still failing - show modal again
		connection_recovery_requested.emit(1)

	return success

func cancel_connection_recovery():
	# Called when user clicks Quit in modal
	connection_recovery_cancelled.emit()
	DebugLogger.info("User cancelled connection recovery", "NAKAMA")
	get_tree().quit()
```

**UI Flow**:
1. Game starts → `attempt_startup_connection()`
2. If stored session exists, try to restore with retries (3 attempts, exponential backoff)
3. If all retries fail due to network error, emit `connection_recovery_requested`
4. UI shows modal: "Cannot connect to cloud. [Retry] [Skip Login]"
5. User clicks Retry → `retry_connection()` → single attempt
6. User clicks Skip Login → Use LocalSaveManager for offline play
7. User clicks Quit → `cancel_connection_recovery()` → exit game

## Error Handling

### Network Errors
- **Scenario**: No internet connection, server down, DNS failure
- **Detection**: Error message contains network keywords (network, timeout, unreachable, dns)
- **Handling**: Show retry modal with exponential backoff

### Invalid Credentials
- **Scenario**: Wrong email/password, account doesn't exist
- **Detection**: Authentication exception with specific error messages
- **Handling**: Emit `authentication_failed` signal with sanitized error message, show to user

### Expired Session
- **Scenario**: Session token expired locally (timestamp check)
- **Detection**: `session.is_expired()` returns true
- **Handling**: Clear stored session, don't retry - show login screen

### Server-Side Session Invalidation
- **Scenario**: Session invalidated on server (logged out from another device, admin action)
- **Detection**: `get_account_async()` returns exception during restore
- **Handling**: Clear stored session, show login screen

### Email Already Exists
- **Scenario**: User tries to create account with existing email
- **Detection**: "already exists" in error message
- **Handling**: Show "Email already registered. Try logging in instead."

### Account Linking Conflicts
- **Scenario**: User tries to link email that's already used by another account
- **Detection**: Link email exception
- **Handling**: Show "This email is already associated with another account"

## Notes & Decisions

**Decision 1**: Use `authenticate_email_async()` instead of `authenticate_custom_async()`
- **Rationale**: Simpler implementation, no server hooks required, built-in bcrypt password hashing
- **Trade-off**: Email field can still be used as arbitrary username (doesn't need to be valid email format)
- **Alternative considered**: Custom auth with server hooks (rejected - overcomplicated for no benefit)

**Decision 2**: Preserve hybrid cloud/local save pattern
- **Rationale**: Matches existing LocalSaveManager implementation, allows offline play
- **Flow**: Cloud saves when authenticated, local saves when offline, migration when authenticating
- **Reference**: [nakama-integration.md](.claude/docs/nakama-integration.md) documents this pattern as established
- **Alternative considered**: Cloud-only (rejected - removes existing feature, worse UX)

**Decision 3**: Account linking for device ID → email upgrade
- **Rationale**: Common user flow - start anonymous, upgrade to persistent account
- **Implementation**: Use `link_email_async()` built-in Nakama API
- **UX**: Show "Add Email/Password" button in settings for device ID users

**Decision 4**: Password minimum 8 characters
- **Rationale**: Industry standard, balances security vs usability
- **Enforcement**: Client-side (fast fail) + Nakama server-side (security)
- **Alternative considered**: 6 characters (rejected - too weak)

**Decision 5**: Store session tokens in plaintext JSON file
- **Rationale**: Simple implementation, session tokens are short-lived and refreshable
- **Security risk**: Tokens readable by anyone with file access
- **Mitigation**: Document that users on shared machines should logout
- **Future improvement**: Use OS keychain for token storage (out of scope for v1)

**Decision 6**: Vague error messages for login failures
- **Rationale**: Prevents username enumeration attacks
- **Implementation**: "Invalid email or password" for both wrong email and wrong password
- **Trade-off**: Slightly worse UX (can't tell user which field is wrong), but more secure

**Decision 7**: Server-side session validation on every startup
- **Rationale**: Ensures session hasn't been invalidated server-side (logout from another device, admin action)
- **Performance**: One extra network round-trip on startup (acceptable)
- **Alternative considered**: Skip validation, only check `is_expired()` locally (rejected - misses server-side invalidation)

**Decision 8**: Network error detection via keyword matching
- **Rationale**: Simple, catches common error types without complex exception handling
- **Keywords**: network, timeout, unreachable, connection, timed out, dns
- **Alternative considered**: Error code checking (rejected - error codes vary by Nakama version)

**Decision 9**: Single manual retry instead of retry loop
- **Rationale**: Prevents frustrating UX where retry triggers another 3-attempt backoff
- **Flow**: Auto-retry (3 attempts) → show modal → manual retry (1 attempt) → show modal again if fails
- **Alternative considered**: Manual retry triggers full backoff (rejected - too many retries)

**Decision 10**: Keep local save after migration to cloud
- **Rationale**: Safety - if cloud save fails to load, local save is backup
- **Future**: Can add "Delete Local Save" button in settings after confirming cloud save works
- **Alternative considered**: Auto-delete after migration (rejected - risky, data loss potential)
