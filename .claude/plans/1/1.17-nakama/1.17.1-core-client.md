# Nakama Core Client Architecture

## Overview
Create the minimal Nakama client autoload for GoA. This is the foundation that all other Nakama plans build upon.

**Parent Plan**: [../1.17-nakama-server.md](../1.17-nakama-server.md) (index)

## Purpose
- Initialize Nakama client connection
- Define core signals and state variables
- Establish server configuration

## Server Infrastructure
- **Server**: Nakama 3.x at nakama.goasso.xyz
- **Plugin**: `addons/com.heroiclabs.nakama/` (Godot plugin)
- **Database**: PostgreSQL
- **Protocol**: HTTPS (port 443)
- **Note**: Using existing server from v0.0 (accepts self-signed certs)

### Installing the Nakama Plugin
1. In Godot, go to **AssetLib** tab (top of editor)
2. Search for "Nakama"
3. Install "Nakama Godot 4 client"
4. Go to **Project → Project Settings → Autoload**
5. Click the folder icon next to "Path"
6. Navigate to `addons/com.heroiclabs.nakama/Nakama.gd`
7. Set Node Name to `Nakama`
8. Click **+ Add**
9. **Move it above NakamaManager** using the up arrows (order matters - Nakama must load first)

## Implementation

### 1.1 Create nakama_client.gd Autoload
Clean, minimal autoload script with only essential features.

**File**: `nakama_client.gd` (autoload name: `NakamaManager`)

**Core Components**:
```gdscript
extends Node

# Nakama objects
var client: NakamaClient
var session: NakamaSession

# Server config
const SERVER_HOST = "nakama.goasso.xyz"
const SERVER_PORT = 443
const SERVER_SCHEME = "https"
const SESSION_TOKEN_PATH = "user://nakama_session.dat"

# Server key - loaded from environment variable to keep it out of version control
# Set environment variable NAKAMA_SERVER_KEY before running
# For development: Create nakama_config.gd (gitignored) with get_key() function as fallback
var server_key: String = ""

# Auth state
var is_authenticated = false
var user_id = ""
var username = ""

# Connection state
var is_connected: bool = false  # False until first successful save
var last_successful_save_timestamp: float = 0.0  # For quit warning (see 1.17.6)

# Signals
signal authentication_succeeded(session_data)
signal authentication_failed(error_message)
signal save_conflict_detected(device_save, account_save)  # Used in 1.17.5-migration.md
signal migration_completed(success: bool)  # Used in 1.17.5-migration.md
signal connection_lost()  # Used in 1.17.3-cloud-storage.md, 1.17.6-connection-ui.md
signal connection_restored()  # Used in 1.17.3-cloud-storage.md, 1.17.6-connection-ui.md
```

**Key Principles**:
- Keep it simple - only what's necessary
- No socket connection (not needed for single-player)
- No deprecated functions
- Clean error handling
- All saves are cloud-based (NO local save fallback)

### 1.2 Load Server Key
Load from environment variable or fallback config:
```gdscript
func _load_server_key() -> bool:
	# Try environment variable first
	server_key = OS.get_environment("NAKAMA_SERVER_KEY")

	if server_key.is_empty():
		# Fallback to gitignored config file (for development)
		if FileAccess.file_exists("res://nakama_config.gd"):
			var config = load("res://nakama_config.gd").new()
			server_key = config.get_key()

	if server_key.is_empty():
		push_error("NAKAMA: Server key not found. Set NAKAMA_SERVER_KEY environment variable or create nakama_config.gd")
		return false

	return true
```

### 1.3 Initialize Client
Client setup with error handling:
```gdscript
func _ready():
	if not _load_server_key():
		push_error("NAKAMA: Failed to load server key")
		return

	if not _initialize_client():
		push_error("NAKAMA: Failed to initialize client")
		return

	# Try to restore previous session (implementation in 1.17.2-authentication.md)
	# _restore_session() internally loads stored session data
	await _restore_session()

func _initialize_client() -> bool:
	# Check if Nakama plugin is available
	if not Engine.has_singleton("Nakama"):
		push_error("NAKAMA: Plugin not found. Is addons/com.heroiclabs.nakama/ installed?")
		return false

	client = Nakama.create_client(
		server_key,
		SERVER_HOST,
		SERVER_PORT,
		SERVER_SCHEME
	)

	if not client:
		push_error("NAKAMA: Failed to create client")
		return false

	# Set timeout for operations
	client.timeout = 10  # 10 second timeout

	# Note: Self-signed cert handling for nakama.goasso.xyz
	# In Godot 4, TLS options are set via HTTPClient.tls_options
	# May need: ProjectSettings.set_setting("network/tls/certificate_bundle_override", "")
	# Test with actual server to determine if cert override needed

	return true
```

**Note**: `_restore_session()` is implemented in [1.17.2-authentication.md](1.17.2-authentication.md). It internally calls `_load_session_data()` to retrieve stored session information.

## Failure Modes and Error Handling

### Missing Server Key
- **Scenario**: No environment variable, no config file
- **Handling**: Log error, return from `_ready()`, NakamaManager non-functional
- **User Impact**: Can't authenticate or save (game won't work)

### Missing Nakama Plugin
- **Scenario**: `addons/com.heroiclabs.nakama/` not installed
- **Handling**: Check `Engine.has_singleton("Nakama")`, log error, return early
- **User Impact**: Can't authenticate or save (game won't work)

### Client Creation Failure
- **Scenario**: `Nakama.create_client()` returns null
- **Handling**: Check return value, log error, return false
- **User Impact**: Can't authenticate or save (game won't work)

### Server Unreachable During Session Restore
- **Scenario**: Session restore fails due to network/server down (implemented in 1.17.2)
- **Suggested Flow**:
  1. Show modal: "Cannot connect to cloud. Retry?" [Retry] [Quit]
  2. Retry connection with exponential backoff (3 attempts max)
  3. If all retries fail: Quit to desktop
- **Rationale**: No local saves = no offline mode. Can't play without cloud connection.
- **Implementation**: See [1.17.2-authentication.md](1.17.2-authentication.md)

**Note**: This plan only handles initialization failures. Authentication/connection failures during runtime are handled in [1.17.2-authentication.md](1.17.2-authentication.md).
